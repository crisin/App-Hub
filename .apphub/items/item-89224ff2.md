Board write-through leaves .apphub/ changes uncommitted in every project repo; today they are committed by hand ("chore(board): …" commits). Automate it, per repo:

- **When:** debounced — after the last board write in a repo, wait ~2 min of quiet (APPHUB_BOARD_COMMIT_DELAY), then commit. Drag-and-drop bursts and runner note streams become one commit.
- **What:** only the board — `git commit -F <msg> -- .apphub/` (a pathspec implies --only: the user's own staged changes stay staged and are never included).
- **Message:** a generated logbook entry from the diff of HEAD vs. working copy of each changed item file: `chore(board): <summary>` plus bullets like `item-x "Title": plan → review`, `+2 notes on item-y`, `new: item-z "Title"`, `removed: …`, `reordered: n items`. Why = "board state written through by the hub", Verified = "generated from the file diff".
- **Guards:** skip (retry later) while the repo is mid-merge/rebase/cherry-pick (.git/MERGE_HEAD, rebase-merge/, …), on a detached HEAD, or with conflicts in .apphub/; never commit inside .worktrees/; never push.
- **Switch:** Settings toggle (default on) + per-project opt-out `boardAutoCommit: false` in .apphub.md.
- **Docs:** concepts/board-files.md (sync rules), howto/two-machines.md (routine shrinks to pull/push), CLAUDE.md git section.

Verify with a throwaway repo: a burst of moves → exactly one commit with the right bullets; an unrelated staged file stays staged and uncommitted; mid-merge → no commit.
