# Feature tour

A walk through the hub, page by page, then the things that live between pages. For the "how"
of each feature follow the links.

## The pages

### Dashboard (`/`)

All projects as cards with name, status, tags and template, from three sources: the hub itself
(slug `hub`), `projects/` and registered repos. **+ New Project** scaffolds from a template,
**Sync** re-reads `.apphub.md` and board files from disk (do it after `git pull`). The `×` on a
card removes a scaffolded project, unregisters an external one, and refuses for the hub.

### Project page (`/project/<slug>`)

One project in depth: description and **context** (both editable in place; the context goes
into every coding-agent prompt for this project), the **phase timeline** (milestones with
completion, reorderable), the project's items by stage, and the **suggest panel**: AI task
suggestions generated by Claude Code from a summary of the project (metadata, architecture
graph, existing items) so it does not repeat what is already on the board.

### Board (`/board`)

The six-lane pipeline across all projects, with a project filter. When exactly one project is
selected, lanes can be grouped by its phases. Drag and drop moves items between lanes and
reorders them; dropping into **claude** starts the runner. The detail drawer edits title,
description, priority, type, labels, parent, phase, dependencies (`blocked_by`, `relates_to`),
and holds notes and attachments. The **runner panel** shows the live run: state, current item,
elapsed time, and the agent's output including its tool calls, streamed over SSE.
[Work with the board](../howto/board-workflow.md).

### Reviews (`/reviews`, `/reviews/<branch>`)

Pending agent branches per project. Open one for commits, diff stat and full diff. **Merge**
creates a `merge(board): <item>` logbook commit on the base branch and moves the item to
**done**; **Discard** removes worktree and branch. [Review agent branches](../howto/reviews.md).

### Agents (`/agents`)

The agents from `agents/*.md` with their provider and model, which providers are reachable right
now, and a prompt box to run one. [Agents and the debate](../howto/agents.md).

### Templates (`/templates`)

The template catalogue from `templates/*/template.json`: Tauri 2, SvelteKit, Next.js, Expo,
Kotlin Multiplatform. [Create a project](../howto/new-project.md) explains the scaffold and
how to add a template.

### Logs (`/logs`)

The structured activity log from SQLite, filterable by level (`debug` to `error`) and category
(`board`, `claude`, `project`, `sync`, `auth`, `system`, `agents`). Run transcripts are files:
`logs/runs/` for coding runs, `logs/agents/` for debates.

### Architecture (`/architecture`)

The hub's own codebase as a graph, discovered by parsing imports, `fetch` calls, SQL statements
and the filesystem: pages, API routes, server modules, database tables, templates, child
projects and the shared package as nodes; `fetch`, `import`, `query` and `created-from` edges.
**2D** is Cytoscape with a dagre layout, **3D** is a WebGL force graph you can fly through. A
detail panel shows the selected node, a settings panel filters node types. This page is the seed
of the visualization pillar on the [roadmap](../roadmap.md).

### Settings (`/settings`)

**Interface**: theme presets, light/dark, density, translucency, font size, all stored in the
local database. **Auth & users**: the dev auth system for spawned projects (below).

### Help panel (`?` or F1)

This wiki, inside the app. It opens on the article that explains the current page, follows
relative links in place, has a searchable table of contents and a back stack. The content is
the `docs/` folder of the repo, rendered on request, so every docs commit is live after a
reload. [Writing docs](../howto/write-docs.md).

## Across pages

### Projects are repos, boards are files

`.apphub.md` marks a repo as a project and carries its metadata. `.apphub/items/*.md` and
`.apphub/phases.md` are the board. SQLite indexes them and can be deleted at any time.
Consequences: boards travel through git, two machines share one board, agents can read their
work items as files, and the board is a graph with explicit edges.
[Board files](../concepts/board-files.md), [two machines](../howto/two-machines.md).

### The runner and coder backends

One item at a time, highest priority first, blockers respected. Each run gets a worktree and a
branch; Node workspaces get their `node_modules` linked in, Rust repos a shared cargo target
dir. Claude Code is the default backend; the label `aider` switches to aider with a local Ollama
model. [The runner](../concepts/runner.md).

### Dependencies, phases, labels

`blocked_by` gates the runner and lets you queue whole chains; `relates_to` and `parent` are
soft structure. Phases are per-project milestones with completion percentages. Two labels are
automation switches: `aider` (backend) and `debate` (start a critic/advocate/judge debate on
creation and attach the verdict as a note).

### Talking agents and the debate

Agents are markdown: frontmatter picks provider and model, the body is the system prompt.
Providers: Ollama, any OpenAI-compatible server, Anthropic. The debate workflow is the first
built-in multi-agent workflow; more are planned as data, see the roadmap's agent Baukasten.

### Dev auth for spawned projects

The hub runs a small central auth service at `/api/dev/*` that scaffolded apps can use during
development: users with scrypt-hashed passwords, HS256 JWTs with refresh tokens, API keys. A
creator account is made on first launch; manage users under Settings → Auth. CORS is open on
these routes on purpose, because the spawned apps run on other ports. It is a development
convenience, not protection for the hub itself, see [trust model](../concepts/trust-model.md).

### The git logbook

Every change to the hub and to its projects is a commit with `Why / What / Verified /
Follow-up`. `npm run logbook` reads it. The runner tells coding agents to write the same
format, the review lane's merge commits follow it too. [The git logbook](../concepts/logbook.md).

### CLI and API

The CLI (`npm run cli -- …`) is a thin client of the HTTP API; everything the UI does is an
endpoint that answers `{ ok, data?, error? }`. Coding agents use the same API to post progress
notes. [CLI](../reference/cli.md), [HTTP API](../reference/api.md).

### Always on

macOS launchd agent or Windows Task Scheduler task, both running `scripts/start.mjs` on
`127.0.0.1:5174`. [Run it permanently](../howto/deploy.md).

### Dogfooding

The hub is project `hub` on its own board. Its roadmap items run through its own runner and
review lane, in worktrees under the hub repo. After merging hub changes, restart the server.
